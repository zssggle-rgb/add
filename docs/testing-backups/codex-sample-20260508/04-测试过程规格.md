## 1. 测试过程总览

本项目以人工验收为主，自动化作为可选增强。测试过程必须加载真实被测对象 `/Users/sjs/add/index.html`，不能连接无关服务或生成替代页面。

## 3. 人工验收过程

### PROC-001 本地功能验收

| 字段 | 内容 |
|------|------|
| 目标 | 验证 add 页面核心功能可用 |
| 优先级 | P0 |
| 启动 | 用浏览器打开 `file:///Users/sjs/add/index.html` |
| 前置检查 | 页面标题显示“加法器”，两个输入框可见 |
| 执行用例 | TC-DELIVERY-001, TC-UI-STRUCT-001, TC-CALC-001..004 |
| 证据 | 记录实际结果；必要时截图保存到 `test-results/manual/PROC-001/` |
| 停止和收尾 | 清空两个输入框，确认页面回到 `0` |

步骤：

1. 打开页面。
2. 确认两个输入框和结果区存在。
3. 依次执行核心计算用例。
4. 每个用例记录实际显示值。
5. 任一 P0 失败时停止后续非 P0 测试并记录缺陷。

### PROC-002 输入验证验收

| 字段 | 内容 |
|------|------|
| 目标 | 验证非法输入被拒绝，且错误可恢复 |
| 优先级 | P0 |
| 启动 | 页面处于正常状态，结果显示 `0` |
| 执行用例 | TC-VALID-001..005, TC-STATE-001 |
| 证据 | 记录错误显示、错误样式、恢复后结果 |
| 停止和收尾 | 清空输入框，确认无错误样式 |

步骤：

1. 输入 `a` 和 `5`，确认错误。
2. 输入 `--5` 和 `3`，确认错误。
3. 输入 `1..2` 和 `3`，确认错误。
4. 输入 `5.` 和 `3`，确认错误，不允许显示 `8`。
5. 输入 `1e5` 和 `2`，确认错误，不允许显示 `100002`。
6. 从错误状态改为 `3` 和 `5`，确认恢复为 `8`。

### PROC-003 交互和可访问性验收

| 字段 | 内容 |
|------|------|
| 目标 | 验证基础视觉交互、移动端布局和可访问性属性 |
| 优先级 | P1 |
| 启动 | 页面加载完成 |
| 执行用例 | TC-UI-FOCUS-001, TC-UI-RESP-001, TC-UI-TRANSITION-001, TC-UI-SELECT-001, TC-A11Y-001 |
| 证据 | 桌面和移动视口截图；源码检查记录 |
| 停止和收尾 | 恢复默认视口 |

步骤：

1. 用 Tab 在两个输入框之间切换，确认 focus 可见。
2. 将浏览器视口设为 320x640 和 480x800，确认无横向溢出。
3. 将结果从 `8` 更新为 `9`，确认结果元素具备 150ms 过渡定义。
4. 双击结果区，确认当前结果文本被选中。
5. 检查输入框 label/aria-label 和结果区 aria-live 属性。
3. 检查源码中 `label`、`aria-label`、`aria-live`、`aria-atomic` 是否存在。

## 4. 可选自动化过程

如后续自动化，建议只创建一个与项目结构匹配的目录：

- 测试目录：`e2e/specs/`
- 被测对象：`file:///Users/sjs/add/index.html`
- 截图证据：`test-results/autopilot-screenshots/add/<case_id>/`

自动化不得创建 `frontend/tests/`、`backend/tests/` 等与本项目结构不符的目录。

建议命令：

```bash
cd /Users/sjs/add/e2e
npx playwright test
```

该命令只有在项目已显式安装 Playwright 后才可作为正式执行命令。未安装时，测试过程状态应为“未自动化”，不能反复返工。

## 5. 失败处理

| 失败类型 | 判定 | 处理 |
|----------|------|------|
| 产品失败 | 用例依据明确，实际结果不符合预期 | 记录缺陷，进入修复 |
| 用例错误 | 用例预期无法追踪到依据，或与依据冲突 | 退回测试用例规格修正 |
| 环境失败 | 浏览器、文件路径、依赖不可用 | 记录环境问题，不修改产品代码 |
| 自动化缺失 | 无测试框架或命令 | 保留人工过程，不生成伪自动化 |

# add 项目测试管理文档

本文档集是按 ISO/IEC/IEEE 29119-3 的测试文档结构、ISTQB CTFL 的测试设计方法、NASA SWE-072 的双向追踪思想，为 add 项目生成的裁剪版样例。

## 裁剪说明

本项目采用裁剪符合性，不生成组织级测试政策、状态报告、完成报告、事件报告等运行期文档。当前样例只覆盖从测试计划到测试过程的前置测试资产。

| 文档 | 对应标准概念 | 用途 |
|------|--------------|------|
| [01-测试计划.md](01-测试计划.md) | Test Plan | 定义测试范围、风险、策略、完成准则 |
| [02-测试模型规格.md](02-测试模型规格.md) | Test Model / Test Design Specification | 从需求、设计、源码推导测试模型和覆盖项 |
| [03-测试用例规格.md](03-测试用例规格.md) | Test Case Specification | 列出正式测试用例，要求每条用例有依据和预期来源 |
| [04-测试过程规格.md](04-测试过程规格.md) | Test Procedure Specification | 定义执行顺序、启动、证据、收尾 |
| [05-需求测试追踪矩阵.md](05-需求测试追踪矩阵.md) | Test Traceability Matrix | 保证需求到测试、测试到依据的双向追踪 |

## 关键规则

1. 测试计划不直接批量生成测试用例。
2. 测试用例必须从测试模型和覆盖项派生。
3. 每条测试用例必须包含测试依据、来源引用和预期结果来源。
4. 没有依据的推断项只能进入 TBD，不能进入正式测试实现。
5. 产品契约明确不支持的行为不能生成“应支持”的成功用例。

## 本样例的结论

当前正式测试范围为 UI、E2E/验收、交付冒烟和基础可访问性验证。UNIT、API、后端集成、性能、安全扫描不进入正式测试用例清单。

旧方案中的两个问题已被模板约束纠正：

- `5.` 不是合法成功输入；源码要求 `parseFloat` 完整消耗字符串，因此应显示错误。
- 科学计数法不是 MVP 支持范围；可作为不支持输入的负向验证，不能作为成功计算用例。

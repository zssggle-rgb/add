## 1. 测试上下文

add 是一个单文件 Web 加法器。产品约束为单 `index.html`、纯 HTML/CSS/JS、无框架、无服务端、无构建依赖、可本地双击打开。核心用户目标是在两个输入框输入数字后实时显示相加结果。

### 1.1 被测项

| 被测项 ID | 被测项 | 范围 |
|-----------|--------|------|
| TI-001 | `index.html` 页面结构 | 标题、两个输入框、运算符、结果区、提示文本 |
| TI-002 | 输入验证逻辑 | `validate(value)` 的合法、非法、空输入处理 |
| TI-003 | 计算逻辑 | `calculate(a, b)` 的加法与浮点精度处理 |
| TI-004 | 结果与错误显示 | `showResult(value)`、`showError()` 的 DOM 状态更新 |
| TI-005 | 交互与响应式 | focus、hover、error 动画、移动端布局 |

### 1.2 测试范围

包含：

- 页面可本地打开。
- 两个输入框存在且可输入。
- 合法整数、负数、小数实时相加。
- 空输入按 0 处理。
- 非法输入显示错误。
- focus、错误态、结果区视觉反馈。
- 基础可访问性属性。
- 移动端最小布局冒烟。

不包含：

- 多数字连加、历史记录、科学计算模式。
- 科学计数法作为合法输入。
- 后端 API、数据库、认证、权限。
- 性能压测和自动安全扫描。
- 跨浏览器全量兼容认证。

## 2. 测试沟通

本样例不设置独立测试组织。测试资产以 Markdown 文档保存在 `docs/testing/`，测试结果可由人工记录或由后续自动化测试报告补充。

## 3. 风险登记

| 风险 ID | 风险 | 影响 | 缓解测试 |
|---------|------|------|----------|
| R-001 | 非法输入被 `parseFloat` 前缀解析误判为合法 | 错误结果 | 决策表覆盖 `5.`、`1..2`、`--5`、`.` |
| R-002 | 空输入处理与普通非法输入混淆 | 用户无法得到默认 0 | 等价类覆盖单空、双空 |
| R-003 | 小数加法出现浮点尾差 | 显示不符合预期 | 小数用例覆盖 `1.5 + 2.5` |
| R-004 | 错误状态无法恢复 | 用户修正输入后仍看到错误 | 状态迁移覆盖错误到正常 |
| R-005 | 移动端布局溢出 | 移动端不可用 | 320px/480px 视口冒烟 |
| R-006 | 无障碍属性缺失 | 辅助技术难以识别 | label、aria-live、aria-atomic 检查 |

## 4. 测试策略

| 测试类型 | 状态 | 说明 |
|----------|------|------|
| UI 组件/交互测试 | 适用 | 通过 DOM 和视觉状态验证输入、结果、错误、focus |
| E2E/验收测试 | 适用 | 以用户流程打开页面、输入、观察结果 |
| 交付冒烟测试 | 适用 | 验证 `index.html` 存在并可本地打开 |
| 可访问性冒烟 | 适用 | 验证基础 label 与结果播报属性 |
| UNIT | 不适用 | 当前源码是浏览器内联脚本，无模块导出边界 |
| API | 不适用 | 无后端服务或 HTTP 契约 |
| 集成测试 | 不适用 | 单文件应用，无跨服务集成边界 |
| 性能测试 | 本轮不适用 | 无性能需求和工具链，保留为后续风险项 |
| 安全扫描 | 本轮不适用 | 无服务端和权限面，保留输入安全人工审查 |

## 6. 完成准则

测试计划进入下一阶段前必须满足：

- 所有正式测试用例均能追踪到测试依据。
- 所有正式测试用例均有明确预期来源。
- 所有 P0 覆盖项均至少有一条测试用例。
- 不支持范围内的行为不得生成成功用例。
- 测试过程能说明如何执行、如何记录结果、如何处理失败。

测试执行完成准则：

- P0 用例全部通过。
- P1 用例无阻断失败；如失败，必须有缺陷或风险记录。
- 所有失败均可追踪到具体用例、覆盖项和测试依据。
